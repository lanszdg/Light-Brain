# Light-brain 1.1 技术架构

## 设计理念

模型为光脑提供推理能力。用户的目标、已经取得的证据、可用方法和正在运行的作业属于实例状态。一次模型会话只尝试解决手上的工作。下一次选择由控制器根据可观察状态重新计算。

系统设定了三个证据来源。用户确认意图，运行环境提供真实行为，独立验收判定工程是否达到冻结条件。模型预测可以用于比较方案。一个成功的模型回复必须经过对应候选工程和导出物的程序验收才能形成交付回执。

## 三个子系统

| 子系统 | 自研实现 | 复用的基础设施 |
| --- | --- | --- |
| 认知内核 | 方案契约、分歧判定、动作绑定、目标逆推、作业选择、经验提取 | NetworkX 切出相关依赖、clingo 计算有效事实 |
| 执行宿主 | 工作者协议、受限工程副本、隔离编排、验收和导出 | Git、Copier、OpenHands SDK、Bubblewrap 与 Playwright |
| 状态仓库 | 版本冲突与事件事务、作业租约、回执及方法版本、文件摘要与归属 | SQLite、文件系统、Git bundle |

API 用 FastAPI 和 Uvicorn。主服务创建控制线程并持有同一状态目录独占锁。Worker 通过独立身份经 HTTP 领取作业、续租和回传结果，候选工程在新目录运行。一次委托最多有一个活动作业。实际命令验收运行在 WSL 的 Bubblewrap 中，浏览器验收使用本机 Chromium。模板、试演图、实际写入的源码、候选和 ZIP 都按不同版本登记。

## 从委托到交付

1. 用户交来原话、目标项目，以及可选的已有 Git 工程或验收条件。
2. 模型提出可运行入口、一个或多项开发动作和可观察断言。工程接手会保留私有基线。临场分歧可以先用指定版本观察，也可以等待用户决定。
3. 控制器冻结验收条件。求解器从目标反查能产出所需结果的动作，并沿前置条件寻找可执行作业。
4. 新 Web 工程可以渲染模板、产出交互试演，再以该版本继续开发。默认执行器产生多文件变更。OpenHands 可按受限权限多轮编辑和运行。
5. 验收 Worker 在干净工作副本检验冻结条件。失败回执携带具体输出和版本，进入下一次修复。通过的候选会被打包，最终 ZIP 还会解压运行复验。
6. 主服务记录可分发版本。下一轮修订从当前候选的源码继续。已经交付的版本可独立预览、下载和追溯。
7. 经过验收的检查、适用的自包含 Python CLI 源码可以成为后续操作。跨项目复用需要授权，扩大使用范围需要独立的交付证据。

## 图谱如何产生

SQLite 保存图的修订、委托快照、作业和回执。控制器每次调度从快照、授权和可用方法建立运行时图。Node 可代表目标、解释、开发动作、验收条件、作业、回执、观察、Git 提交和交付。边记录依赖、授权、实测对象或交付依据。

图谱前端用 Canvas 画关系和定位缩略图，节点使用可键盘访问的 HTML 按钮。拓扑布局围绕委托组织关系，分层布局按职责排列。检查器分别列出上游证据和下游结果。聚焦模式突出选中节点前后两层关系，修订时间轴读取历史版本。独立图谱用 API 令牌访问委托，嵌入站点可使用自己的同源服务端桥接。未经授权的访问只看到明确标记的合成示例。

## 文件结构

```text
lb.py                            Python 启动入口
启动光脑.ps1                     项目内环境安装与服务启动
工程依赖/                        Windows、Linux 工具及可选 SDK 依赖锁
src/lightbrain/
  application.py                 API、控制线程、作业协议、版本及产物接口
  controller.py                  作业选择、证据消费、修订和交付
  contracts.py                   可执行方案及验收条件
  inquiry.py                     分歧的证据与选择
  core/                          图计算、事实闭包、经验资格
  model.py / worker.py           模型调用、领取、续租、产物和回执
  store/                         SQLite 架构和事务
  repository.py / host/          Git、工作区、OpenHands、沙箱、构建和发布
  browser_checks.py               浏览器验收
  live_preview.py                 实际 HTTP 预览进程
  recipes.py / recipes_data/      模板目录和可组合组件
  learning.py                    验收方法提取、复用、推广
  implementation_methods.py       实现方法提取和授权落盘
  studio.py / web/                推演图谱路由与浏览器客户端
tests/                           回归、隔离执行和真实模型验收入口
```

默认实例库为 `.lb/state/lightbrain.sqlite3`，Git bundle、归档和截图保存在 `.lb/state/objects/`。推荐用 `LB_HOME` 为独立测试实例指定不同的位置。程序默认监听回环地址。

## 工作台接入

服务端使用 `Authorization: Bearer <token>`，浏览器持有工作台自己的会话即可。工作台保存产品项目 ID 和 LB 委托 ID 的关联。接入系统可以根据自己的权限配置请求创建、读取和操作入口。

| 接入意图 | 方法与路径 |
| --- | --- |
| 从想法开始 | `POST /brains/{brain}/cases`，提供 `idea`、`project`，可选用 `event_id` 保证重试幂等 |
| 读状态、动作版本及证据 | `GET /cases/{id}`、`/jobs`、`/events`、`/graph?revision=…` |
| 修改方向、选择方案、重试 | `POST /cases/{id}/events`，提交 `kind`，必要时提供 `text`；重试可复用同一 `event_id` |
| 查询历史成品 | `GET /cases/{id}/versions` 返回所有通过独立复验的版本 |
| 下载归档 | `GET /cases/{id}/artifacts/{sha256}` |
| 看实际运行 | `POST /cases/{id}/live` 启动限时 HTTP 预览并返回访问地址。可传 `archive_id` 启动已交付的历史版本，运行依据取自该版本的独立复验作业。 |

工作台用户编辑想法时，旧交付版本仍能按历史查询。由工作台校验项目权限，然后把项目映射到服务端保存的委托 ID。候选和导出复验使用既定验收条件。Android 和 iOS 接入方可以使用固定的原生工程、依赖、打包验证和签名渠道消费已核验的业务源码。正式渠道仍由接入产品配置。图谱的修订号反映实际状态快照，交付版本对应用户目标的迭代次数。

## 本地测试

```powershell
$env:PYTHONPATH = (Resolve-Path src).Path
.\.lb\env\Scripts\python.exe -B -m unittest discover -s tests -p 'test_*.py' -v
```

独立测试脚本在 `tests/live_*.py`，可以使用自己的模型配置运行。完整的本地交付范围包括 Web、Python HTTP 和 CLI。原生 App 交给接入产品的原生交付流程。本版本的渠道记录为本地模拟。
